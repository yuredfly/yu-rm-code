## 第一部分：方案一 vs 方案二

### 1.1 一眼对照表

| 对比维度 | **方案一：指定练习图** | **方案二：自选图片** |
|---|---|---|
| 图片来源 | 任务提供 `images/input.png`（960×640） | **自己找**，放 `images/custom.png`，**须注明来源** |
| 图片难度 | 纯色背景、单色目标，**干扰可控** | **必须更有挑战**：≥5 个目标 + ≥1 种分割干扰 |
| 参数 | **任务给定，要求保持不变**（核 5×5、阈值 120、INV、HSV (35,80,80)~(85,255,255)、核 3×3/7×7、面积 100） | **完全自己调**，明文规定"**不能直接照搬指定练习图的数值**" |
| 两条路线 | 都要做，**但轮廓只用 HSV 的开运算结果** | 都要做，**比较后自己选较好的一张**继续 |
| 目标数验收 | **必须 6** | **至少 5** |
| 输出文件名 | `fixed_*.png`（9 个） | `custom_*.png`（9 个） |
| 额外提交 | 说明：**两张 mask 差别 + 四种形态学效果** | 说明：**图片来源 + 目标 + 干扰因素 + 两张 mask 比较 + 选用路线及参数 + 形态学效果 + 目标数** |
| 工作量 | 中（代码为主，参数已给） | **大**（要选图、要调两套参数、要解释为什么选它） |
| 失败风险 | 低（参数已验证可用） | **中高**（选图不当会导致两条路线都分不开） |
| 适合谁 | 想稳过验收、把精力放在理解流程上 | 想把方法用在新数据上、愿意承担调参风险 |
| 是否互斥 | **互斥！只需完整完成其中一种**（引导 p.2 原文："无需两种都做"） | 同左 |

> **【强制】二选一**。两个都做不会加分，反而可能因为方案二没调好而拉低印象分。

### 1.2 方案一：优点 / 缺点

| 优点 | 说明 |
|---|---|
| **参数已给定且经实测可用** | 本图绿 H=59、S=170、V=120，落在 `(35,80,80)~(85,255,255)` 内部且余量充足；灰度 87 vs 阈值 120 方向正确 |
| **两条路线都能成立，便于对比** | 同一张图上比较"靠明暗"与"靠颜色"，概念差异一目了然 |
| **结果可预期、可自检** | 候选轮廓 12（6 主体 + 6 小点）→ 过滤后 6；小点面积 4~16，主体 5030~19792，**相差三个数量级**，面积阈值 100 极其安全 |
| **图形设计有教学意图** | 菱形（fill≈0.50）+ 倾斜方块（0.58）专门用来暴露 `boundingRect` 与 `minAreaRect` 的差别；主体内浅色小孔专门用来观察闭运算 |
| **调试成本低** | 一旦数量不对，能立刻判断是代码问题而不是图片问题 |

| 缺点 | 说明 |
|---|---|
| **学不到"参数怎么选"** | 数值全是给的，容易"抄完就忘"，说不清 120 为什么合适 |
| **不适配别的图** | 换成自选图后这套参数大概率失效（阈值 120 对别的亮度分不一定对） |
| **难度上限低** | 背景纯色、目标纯色，不需要处理光照不均或纹理 |
| **对比深度有限** | 两条路线结果都很干净，说不出"某条路线明显更好"的强结论 |

### 1.3 方案二：优点 / 缺点

| 优点 | 说明 |
|---|---|
| **真正练"参数决策"** | 必须自己观察像素值、打印候选面积分布，才能定阈值——这才是本周能力的核心 |
| **练"方案选择与论证"** | 要比较两张 mask 并说明为什么选某条路线，训练的是判断力而非记忆 |
| **接触真实干扰** | 纹理背景、阴影、近色干扰会暴露灰度阈值的短板，也会逼你理解 S/V 上下界的作用 |
| **挑战开放，展示空间大** | 图片来源、干扰处理过程都是自己的，说明文档更有内容 |

| 缺点 / 风险 | 说明 | 规避办法 |
|---|---|---|
| **选图不当直接失败** | 若两条路线都分不开目标，整个方案作废（任务原文："若两条路线都无法分清目标和背景，应换一张……图片"） | **先只跑分割那一步**验证可行性，再决定是否投入后续 |
| **调参耗时不可控** | HSV 上下界有三个通道、S/V 相互影响，可能反复试 | **每次只改一个界**（引导原文），并打印 `countNonZero` 量化 |
| **H 环形问题** | 目标若偏红（H 跨 0/179），单段 `inRange` 会漏 | 用两段 `inRange` 再 `bitwise_or` |
| **低饱和目标失灵** | 近灰/白色目标 H 不稳定，HSV 路线会失败 | 改用灰度路线，或放宽 S 下界到 30 左右 |
| **说明文档要求更多** | 来源、干扰因素、选路理由都要写 | 边调参边记录（见 1.5 记录表） |
| **提交要带图与来源** | 任务明文："提交时一并提交图片和来源说明" | 提前保存原图链接/出处 |

### 1.6 【可选】如何量化"哪张 mask 更好"（避免只说"感觉更好"）

用 3 个可打印的指标代替主观判断：

| 指标 | 含义 | 在本图（方案一）的参考值 |
|---|---|---|
| `countNonZero(mask)` | 前景像素总量 | 灰度 **67789**、HSV **70180** |
| candidate contours | 过滤前连通区域数 | 两者都应为 **12** |
| 面积分布 | 目标与噪声的分界是否清晰 | 小点 **4~16**、主体 **5030~19792**（分界极清晰） |

**判据**：**目标保留数达标**是硬指标；在都达标的前提下，**误选背景更少**的那张更好。

## 第三部分：代码调试要点

### 3.1 ★ 倒查顺序（最重要的调试纪律，任务原文要求）

**轮廓数不是 6 时，按顺序检查：`mask` → 形态学结果 → 面积阈值。**

```
轮廓数 ≠ 6
├─ ① 看 mask（先打印 countNonZero 和候选面积）
│    ├─ 全黑 / 全白      → 阈值方向或数值错、HSV 上下界错
│    ├─ 黄色也是白        → HSV 上界过大 / 灰度阈值把黄色也收进来
│    └─ 主体是黑          → 阈值类型或颜色范围选反了（轮廓把白色当前景）
├─ ② 看形态学（5 个 countNonZero 一起打印对比）
│    ├─ 四张几乎一样      → 写成链式调用了（约束 1）
│    └─ opened 里绿点还在  → 核太小，或输入根本不是 mask_hsv
├─ ③ 看面积阈值（打印全部候选面积）
│    ├─ 小点面积 ≥ 100    → 阈值太低，或开运算没起作用
│    └─ 主体面积 < 100    → 阈值太高，或 mask 把主体打碎了
└─ ④（最后才看）绘图与中心点 —— 它们不会改变轮廓数量
```

**配套铁律**：
- **mask 不对就先别调轮廓；数量不对就先别调中心点**（引导原文）；
- **每次只改最近新增的那一步**，不要同时改三个参数；
- **每次只改一个 HSV 上下界**，这样才知道是哪项调整起了作用（引导原文）。

### 3.2 分层定位：用中间产物二分查找

| 症状 | 先怀疑的层 | 快速验证 |
|---|---|---|
| 程序启动即退出 | 工作目录 / 相对路径 | 确认 exe 旁边有 `images/input.png` |
| 读图失败 | 路径层 | 打印当前工作目录 + `empty()` 判断 |
| mask 全黑或全白 | 分割层 | `countNonZero(mask)`，对照 67789 / 70180 |
| 轮廓数 0 | mask 层（不是轮廓层） | 看 mask 里目标是否白色、是否单通道 |
| 轮廓数 12 | 形态学层 | 检查轮廓输入是不是 `opened` |
| 轮廓数 20+ | 分割+形态学层 | 面积阈值是否太低；开运算核是否太小 |
| 目标少 1 个 | 分割层 | 某个主体是否被阈值切碎成两块 |
| 框画歪 / 中心点离谱 | 绘图层 | 是否先判 `m00`；坐标是否来自同一张图 |
| 图没保存 | I/O 层 | `output/` 是否存在；`imwrite` 返回值是否检查 |

### 3.5 常见编译期 / 运行期问题与解法

| 报错或现象 | 根因 | 解法 |
|---|---|---|
| MSVC 报"常量中有换行符"等中文注释相关语法错误 | 源码是 UTF-8，MSVC 按 GBK 解析 | CMake 里 `target_compile_options(... /utf-8)` |
| `找不到 opencv_world4140.dll` | 运行时找不到 DLL | 把 `C:\RM\opencv\build\x64\vc16\bin` 加入 PATH，或把 DLL 复制到 exe 旁 |
| Debug 崩溃 / Release 正常（或反之） | Debug 链接了 Release 库 | Debug 配置用 `opencv_world4140d.lib`（CMake 的 `find_package` 已自动处理） |
| `findContours` 相关报错 | 传入的不是单通道二值图 | 确认输入是 mask（`CV_8UC1`），不是彩色图 |
| `medianBlur` 断言失败 | ksize 传了偶数或 `Size` | 传 `int` 奇数（本图 5） |
| 阈值结果与预期相反 | 用了 `BINARY` 而非 `INV` | 目标比背景暗 → `INV` |
| 输出图是一片黑 | 保存了未初始化的 `Mat` | 检查保存前 `Mat` 是否 `empty()` |
| 反复改代码但现象不变 | **旧的 exe / CMake 没重新编译** | 改完确认编译日志里出现了该 .cpp；必要时 `cmake --build build --config Release --clean-first` |
| CMake 目录被占用无法配置 | `build/` 残留或权限不足 | 删除 `build/` 重新配置；确认目录可写 |

> **本次实测踩到过一次第 8 类坑**：用文件改名/移动的方式"恢复"源码后，MSVC 依据时间戳判定无需重编译，
> 导致运行的仍是旧参数的可执行文件（现象是"参数明明改回去了，结果还是 0"）。
> **规避办法**：恢复源码后 `touch` 一下（更新修改时间）或直接 `--clean-first` 重编，并**在终端确认编译日志里出现了 main.cpp**。

### 3.6 调试策略小结（把方法记成三句话）

1. **永远先看中间产物，再看结论**：mask → 形态学 → 轮廓数量 → 测量/绘图，**倒着怀疑会浪费时间**；
2. **把现象变成数字**：`countNonZero`、候选面积、轮廓数——数字能一眼判断对错，看图容易看走眼；
3. **一次只改一个变量，且改完立刻验证**：参数、代码、输入图三者不要同时动。
